Here’s a clean, numbered bullet‑point summary of the pipeline algorithm tailored to your Node setup and config/pillars.json:

Load configuration
1.1. Read config/pillars.json into memory.
1.2. Extract pillars and clusters plus site‑level defaults (tone, domain, etc.).

Iterate over pillars and clusters
2.1. For each pillar (or cluster), load its steps array (outline → paragraphs → linking).
2.2. Start with the first step (usually outline).

Step‑by‑step execution per item
3.1. Outline step (e.g., Sonnet)
3.1.1. Build a prompt using the item’s id, h1, and instructions.
3.1.2. Call the model to output a structured JSON outline (H2/H3 + key points).
3.1.3. Save result to data/pillars/outline/pillar-<slug>.json. 3.2. Paragraphs step (e.g., Haiko)
3.2.1. Read the outline JSON for the current item.
3.2.2. Build a prompt that says “turn each section into 1–2 opinionated paragraphs, 300–500 words per section.”
3.2.3. Call the heavier model and save the prose output to data/pillars/paragraphs/pillar-<slug>.json. 3.3. Linking / QA step (e.g., Sonnet again)
3.3.1. Read the paragraphs JSON.
3.3.2. Prompt the model to “add or fix 1–2 internal links per section to cluster and verdict pages.”
3.3.3. Save the linked‑version to data/pillars/merged/pillar-<slug>.json.

Repeat and aggregate
4.1. Loop through all pillars and clusters, running the same 3‑step sequence for each.
4.2. Optionally, run a final “QA check” script over the merged JSONs (word count, link count, missing H1, etc.).

Publish‑ready stage
5.1. In a later stage, your HTML renderer reads the merged/pillar-<slug>.json files.
5.2. Converts each section’s H2/H3, prose, and links into a fully‑rendered HTML page on your site.

This keeps your pipeline config‑driven, model‑aware, and cleanly split between “thinking” (Sonnet) and “writing” (Haiko).
