BooksVersusMovies.com — New Movies Publishing Workflow
=======================================================
Last updated: April 3, 2026

This document covers the full end-to-end process for adding new
comparison pages to booksversusmovies.com, from research to deploy.

---

STEP 1 — GATHER DATA FOR NEW MOVIES
-------------------------------------
For each new movie, collect:

  1. Title
  2. Amazon affiliate link (amzn.to short link)
  3. Image filename (e.g. gone-girl.jpg — use slug format, lowercase, hyphens)
  4. YouTube trailer URL (https://www.youtube.com/watch?v=XXXXXXXXXXX)

Add these to next_movies.csv in the /next_movies/ folder:

  title,image,affiliate_link,trailer_url
  Gone Girl,gone-girl.jpg,https://amzn.to/XXXXXXX,https://www.youtube.com/watch?v=XXXXXXX

NOTE: Check that the YouTube video allows embedding. If blocked, the
facade pattern (thumbnail linking to YouTube) still works fine — the
script handles this automatically.


---

STEP 2 — UPDATE next_movies.js WITH EDITORIAL DATA
----------------------------------------------------
Open /next_movies/next_movies.js and add a new entry to the PAGES array
for each book. Each entry needs:

  slug          — URL-safe filename (e.g. 'gone-girl')
  title         — Full title (e.g. 'Gone Girl')
  genre         — Genre tag (e.g. 'Psychological Thriller')
  author        — Author name
  bookYear      — Year novel was published
  director      — Film director name
  filmYear      — Year film was released
  verdict       — 'book', 'film', or 'tie'
  verdictText   — 'Book Wins', 'Screen Wins', or 'Too Close to Call'
  affiliateLink — Amazon affiliate link
  image         — Image filename (must match /images/ folder)
  youtubeId     — YouTube video ID (11 characters after ?v=)
  trailerNote   — Cast and release date line
  metaTitle     — SEO title (50-60 chars, include "Book vs Movie")
  metaDesc      — SEO meta description (140-160 chars)
  subtitle      — Page subtitle (Book year vs Movie year, director)
  storyBrief    — 2-3 paragraph story summary
  differences   — Array of {heading, text} objects (aim for 5)
  readFirst     — "Should You Read First?" paragraph
  verdictBox    — Final verdict paragraph
  related       — Array of {href, label} for 3 related pages


---

STEP 3 — ADD BOOK COVER IMAGES
--------------------------------
Add book cover images to the /images/ folder in the ROOT directory
(not inside /next_movies/).

Naming convention: use the slug as the filename
  e.g. gone-girl.jpg, the-road.jpg, normal-people.jpg

Recommended image size: ~300x450px (book cover proportions)
Format: JPG preferred, PNG acceptable


---

STEP 4 — GENERATE HTML PAGES
------------------------------
Navigate to the /next_movies/ folder and run:

  node next_movies.js

This generates one HTML file per entry in PAGES array.
Files are written to the /next_movies/ folder.

Check the console output — it will list every file generated.


---

STEP 5 — RUN QA CHECKS
------------------------
From inside /next_movies/, run:

  node script_qa.js

The QA script checks each page for:

  ✓ <title> tag present and not too short
  ✓ <meta name="description"> present and correct length
  ✓ Google Analytics tag (G-P0DY0XDWVV)
  ✓ Schema.org JSON-LD Review markup
  ✓ Affiliate disclosure near buy button
  ✓ "I earn" not "we earn" in disclosures
  ✓ Buy button with Amazon affiliate link
  ✓ Trailer thumbnail present
  ✓ Trailer note present
  ✓ Book cover image tag present
  ✓ Book cover image file exists on disk (checks ../images/)
  ✓ Alt text on book cover (keyword-rich)
  ✓ Alt text on trailer image
  ✓ Verdict badge present with correct class
  ✓ Related section present
  ✓ Footer affiliate disclosure present
  ✓ About link in nav and footer

Output key:
  ✅  Page passes all checks
  ⚠️  Page has warnings (worth reviewing, not blocking)
  ❌  Page has issues (must fix before publishing)

Fix any ❌ issues before proceeding to Step 6.
🟡 warnings are advisory — use your judgment.


---

STEP 6 — MOVE FILES TO ROOT
-----------------------------
Once QA passes, move the HTML files from /next_movies/ to the site root.

Windows:
  move *.html ..

Mac/Linux:
  mv *.html ..

Do NOT move next_movies.js, script_qa.js, or next_movies.csv —
those stay in /next_movies/.


---

STEP 7 — UPDATE SITEMAP
-------------------------
From the ROOT directory, run:

  node script_update_sitemap.js

This scans all .html files in root and regenerates sitemap.xml
with today's date as the lastmod for all pages.


---

STEP 8 — UPDATE INDEX PAGE
----------------------------
Open script_update_index.js and add each new page to the correct
section in the SECTIONS array. Each entry needs:

  file    — HTML filename (e.g. 'gone-girl.html')
  image   — Image filename (e.g. 'gone-girl.jpg')
  genre   — Genre tag
  title   — Display title
  author  — Author and star/director line
  footer  — Release info and verdict

Then run from the ROOT directory:

  node script_update_index.js

This rebuilds index.html with all pages organized into sections.


---

STEP 9 — FINAL QA ON ROOT
---------------------------
Run QA one more time from the ROOT directory to confirm everything
looks clean after moving files:

  node script_qa.js

All pages should show ✅.


---

STEP 10 — COMMIT AND DEPLOY
-----------------------------
From the ROOT directory:

  git add .
  git commit -m "Add [X] new comparison pages: [titles]"
  git push

Netlify auto-deploys on push. Deployment typically takes 30-60 seconds.
Check https://booksversusmovies.com after deploy to verify pages are live.


---

STEP 11 — REQUEST INDEXING IN SEARCH CONSOLE
---------------------------------------------
Go to https://search.google.com/search-console

For each new page:
  1. Paste the full URL (e.g. https://booksversusmovies.com/gone-girl.html)
  2. Click "Request Indexing"
  3. Wait for confirmation before moving to next URL

Note: Google has a daily quota for indexing requests (~10-15 per day).
Prioritize 2026 release pages first as they have the most time-sensitive
search potential.


---

SCRIPTS REFERENCE
------------------

Script                        Location        Purpose
-------------------------------------------------------------------------------------
next_movies.js               /next_movies/   Generates HTML pages from PAGES array
script_qa.js                 /next_movies/   QA checks on generated pages
script_update_sitemap.js     /root/          Regenerates sitemap.xml
script_update_index.js       /root/          Rebuilds index.html
script_add_disclosure.js     /root/          Adds affiliate disclosure (one-time)
script_add_about_link.js     /root/          Adds About link to nav (one-time)
update_alt_text.js           /root/          Updates image alt text (one-time)
add_schema.js                /root/          Adds Schema.org markup (one-time)
add_analytics.js             /root/          Adds Google Analytics tag (one-time)
script_i_vs_we.js            /root/          Fixes "we earn" to "I earn" (one-time)
remove_emojis.js             /root/          Removes emoji from verdict badges (one-time)
update_meta.js               /root/          Updates title and meta descriptions (one-time)
update_trailer_notes.js      /root/          Updates trailer cast and release dates (one-time)


---

ADDING A NEW MOVIE CHECKLIST
------------------------------
Use this checklist for each new comparison page:

  [ ] Title, affiliate link, image filename, YouTube URL collected
  [ ] Entry added to PAGES array in next_movies.js
  [ ] Book cover image added to /images/ folder
  [ ] node next_movies.js run — HTML file generated
  [ ] node script_qa.js run — all checks passing
  [ ] HTML file moved to root
  [ ] Entry added to SECTIONS in script_update_index.js
  [ ] node script_update_sitemap.js run
  [ ] node script_update_index.js run
  [ ] node script_qa.js run from root — all clean
  [ ] git add . && git commit && git push
  [ ] Indexing requested in Google Search Console


---

NOTES
------
- Always run scripts from the correct directory (see Scripts Reference above)
- The QA script checks ../images/ automatically when run from /next_movies/
- Netlify deploys automatically on every git push — no manual deploy needed
- Google Search Console has a daily indexing quota — prioritize 2026 pages
- For future pages, Claude can generate the editorial content given:
    title, affiliate link, image filename, YouTube URL
